# Шаблон сообщения контакту по тестовому заданию

Ниже — вариант сообщения, который показывает зрелый post-implementation review,
не превращая его в оправдание и не перекладывая ответственность на AI.

## Вариант сообщения

Здравствуйте!

После реализации я отдельно провёл техническую проверку решения и зафиксировал
текущее состояние MVP.

Что уже работает по сценарию задания:

- FastAPI backend с `POST /chat` и `GET /history`;
- React/Vite/TypeScript frontend;
- четыре специализированные роли AI с отдельными system prompts;
- in-memory история последних пяти успешных запросов;
- loading state, копирование ответа и базовая валидация.

В ходе post-implementation review я обнаружил несколько пунктов, которые важно
исправить до публикации:

- frontend quality gate пока не проходит из-за type-only import и правила React Hooks;
- Markdown был заявлен в первоначальном плане, но в текущем коде ответ ещё
  отображается обычным текстом;
- backend слишком подробно отдаёт текст исключения клиенту;
- URL API захардкожен для localhost;
- history нужно расширить полями `mode`, `id`, `created_at` и восстанавливать
  полный exchange;
- отсутствуют тесты, корневой README и единая конфигурация запуска.

Это не меняет основную архитектуру, но отделяет демонстрационный каркас от
готового MVP. Я подготовил техническое ТЗ, критерии приёмки и план доведения
решения до состояния, которое можно безопасно показать локально или развернуть
как preview.

План следующего этапа:

1. закрыть build/lint;
2. добавить Markdown и безопасный error contract;
3. покрыть validation/history/provider failure тестами;
4. вынести конфигурацию в environment variables;
5. завершить mobile layout;
6. подготовить бесплатный preview deployment с server-side API key.

Отдельно отмечу: во время работы AI coding agent сформировал часть решения в
текстовом ответе, но не применил её как корректные файловые изменения. Поэтому
я не считаю рассуждение агента доказательством готовности продукта и проверяю
результат по working tree, build, lint, тестам и ручному сценарию.

С уважением,

`[Имя]`

## Что не стоит писать контакту

- «Бесплатный токен всё сломал» без лога HTTP-ошибки или provider response.
- «AI не смог, поэтому файлы не создались».
- «Проект полностью готов», если build/lint не проходят.
- Реальный API key, содержимое `.env` или полную Aider history.
